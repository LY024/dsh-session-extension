# dsh-session-extension

**把上一次提问拿回来，改一改，再发一次。** 像 Codex 里「编辑上一条消息重新发送」那样，不用重开对话，也不用复制粘贴历史。

装完之后 DSH 里会多出三处入口：

| 入口 | 位置 | 能做什么 |
| --- | --- | --- |
| **左侧栏「会话重发」** | 侧边栏全局图标列（和「插件」「定时」并排） | 打开「会话重发台」：列出所有可见会话，逐个「编辑重发」 |
| **「编辑上次提问」按钮** | 会话输入框上方 | 一键把当前会话的上一条提问拉进编辑框 |
| **「编辑上次提问…」菜单项** | 侧边栏会话行「…」菜单 | 不用先打开会话，直接从列表里改 |

> 这个插件属于「会话管理增强」这一类，但它**不搬会话文件、不改会话日志**。
> 需要跨工作区搬会话的话，看参考实现
> [DDDMUC/dsh-session-relocate](https://github.com/DDDMUC/dsh-session-relocate)。

---

## 它到底怎么「重发」

DSH 的会话日志是只追加的：已经落盘的一轮没法原地改。所以「编辑上一条提问再发送」
用 DSH 自己的**分叉**语义实现，而不是伪造日志：

1. 插件从会话日志里找出**最后一条用户亲手发的提问**（跳过注入上下文、压缩检查点、
   替换副本和纯附件消息）；
2. 在它**之前**的位置 `fork` 出一个新会话 —— 新会话拥有此刻之前的全部历史；
3. 打开新会话，把你在对话框里改好的文字放进它的输入框；
4. 点发送（或用「重发并发送」一步到位）—— 新的一轮从这里开始。

**原会话一个字节都没动**：它还在侧边栏原位，随时可以点回去对照。新分支的标题会带上
分叉标记（DSH 自己的 `increaseTitle`），不会和原会话混在一起。

如果你只是想复用上一句话、不想开新分支，用「仅载入输入框」：文字会填进**当前**会话的
输入框，发送后作为一条新消息追加（Codex 里按 ↑ 召回上一条的效果）。

## 安装

~~~bash
# 从 npm 装（发布后）：
dsh plugin --profile web add dsh-session-extension

# 从源码装（把路径换成你 clone 下来的目录）：
dsh plugin --profile web add <你 clone 下来的 dsh-session-extension 目录>
~~~

主机侧是 Node 模块，装完**重启一次 `dsh web`**（或用 Plugins 页面里的插件管理器安装，
它会尝试热加载）。

装好后的自检：

~~~bash
curl http://127.0.0.1:3080/api/dsh-session-extension/status
~~~

返回 `{"ok":true, ...}` 就说明主机侧在线；刷新页面后左侧栏应出现「会话重发」图标。

## 用起来

### 方式一：输入框上方

打开任意一个聊过的会话，输入框上方会有一条 **↩ 编辑上次提问**。点它：

- 中间弹出编辑框，里面就是上一条提问的原文；
- 改完点 **重发并发送** → 从那条提问之前分叉，文字进新分支的输入框并自动发送；
- 或者点 **仅载入输入框** → 只把文字填进当前输入框，不分支。

编辑框里支持 `Ctrl/Cmd + Enter` 直接重发，`Esc` 取消。

### 方式二：左侧栏「会话重发台」

点左侧栏的「会话重发」图标，右侧主区会打开一页会话列表：

- 顶部可以按标题 / 目录搜索；
- 每一行显示标题、工作区、最后更新时间，运行中的会话带绿点；
- **编辑重发** 直接打开该会话的编辑框（不用先点开会话）；
- **打开** 就是普通地打开这个会话。

### 方式三：会话行「…」菜单

侧边栏任意会话行 → **…** → **编辑上次提问…**，同样直接进编辑框。

## 配置

`cordis.patch.yml` 里这一行的 `config`（profile 层可覆盖）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `bridgePrefix` | `/api/dsh-session-extension` | 主机只读桥接前缀。改动后客户端自动跟随（通过引导全局下发）。 |
| `allowedHosts` | `[]` | 额外允许的 `Host`（主机名，不含端口）。默认只认回环 + `webServer.host`。 |
| `allowedOrigins` | `[]` | 额外允许的 `Origin`（完整 origin，如 `http://localhost:5173`）。给 Vite/开发代理用。 |
| `maxSessions` | `40` | `/sessions` 一次最多返回多少条（上限 200）。 |
| `withTitles` | `false` | `/sessions` 是否顺带读标题（读标题要逐个折叠日志；开启后只对 ≤ 20 条生效）。 |

## 桥接 API（主机侧，只读）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `<prefix>/status` | 版本、前缀、能力。 |
| POST | `<prefix>/sessions` | `{ limit?, withTitles? }` → `{ ok, total, sessions[] }`；只读会话 header，不打开正文。 |
| POST | `<prefix>/last-prompt` | `{ sessionId }` → `{ ok, seq, prevSeq, text, time, images, files, replied, header }`。`prevSeq` 就是 fork 的闭区右端点；为 `null` 表示这条提问没有更早的历史。 |

失败一律是 `{ ok: false, code, message }`。POST 必须带 `Content-Type: application/json`；
来源校验失败回 `403 forbidden`，媒体类型不对回 `415 unsupported-media-type`，
请求体超过 64 KB 回 `413`。

## 安全边界

桥接直接挂在 DSH 的 `node:http` 上，没有 cookie、没有 token，所以插件自己做了防护：

- **Host 校验**：只接受回环主机名（`localhost`、`127.0.0.0/8`、`::1`）或 `webServer.host`
  绑定的地址，挡住 DNS rebinding；
- **Origin / Sec-Fetch-Site 校验**：带 `Origin` 时必须是同源，`Sec-Fetch-Site: cross-site`
  直接拒绝；开发代理用 `allowedOrigins` 显式放开；
- **强制 JSON Content-Type**：跨源「简单请求」只能发 `text/plain`，要求 JSON 就把普通 CSRF
  挡在预检上（本服务不应答 CORS 预检）；
- **只读**：三个接口都只读会话数据，不写日志、不动文件；真正的写操作（分叉 / 发送）
  全部由浏览器端通过 DSH 自己的公开接口完成，走的是 DSH 原有的权限模型。

## 已知限制

- **重发一定会新建一个分支**，这是 DSH 只追加日志的必然结果；原会话不会被「改写」。
  如果你要的是「原地改掉」，那需要改日志格式，本插件刻意不做。
- **只认用户亲手发的提问**：注入的上下文、压缩检查点、子代理消息、纯图片消息都不会被
  当成「上一次提问」；所以某些会话可能提示「还没有可以编辑的提问」。
- **最后一句提问没有更早的历史**（整个会话只有这一问）时不能分叉，只能「仅载入输入框」。
- 「编辑上次提问」入口依赖会话 composer 的 `inputActions`（`setDraft` / `submit`）。
  如果宿主版本没有这个公开面，插件会退化成「把文字放进一个只读框让你手动粘贴」，
  并明确告诉你。
- 会话列表复用宿主自己给插件的 `useSessions` / `useWorkspaces`，所以顺序、标题、
  归档过滤和侧边栏一致；宿主没提供这两个 hook 时，面板会显示相应提示，其余入口不受影响。

## 开发与测试

~~~bash
node --test
~~~

`test/last-prompt.test.js` 覆盖「上一次提问」的识别规则：用户来源过滤、追加/替换副本区分、
空白文本、fork 边界、助手回答判定。全部用合成数据，不碰真实会话。

目录：

~~~
src/last-prompt.js   纯函数：从事件流里找上一次提问
src/plugin.js        主机侧：只读桥接 + 来源校验
lib/client.js        网页端：侧边栏入口、composer 入口、菜单项、编辑对话框
test/                单元测试
~~~
